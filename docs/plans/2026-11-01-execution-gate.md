# B 部分：安全执行门实现计划

## 范围

本变更实现 `docs/05-六人分工与里程碑.md` 中 B 的首个可验收闭环：

- 服务端创建操作快照并计算风险级别；
- 参数摘要、计划版本和确认有效期；
- 黄色操作确认、红色操作独立强验证；
- 业务日转账额度的原子预占，防止并发拆单绕过阈值；
- Outbox、Worker 租约、幂等提交和未知结果核验；
- 追加式审计事件。

## 边界

`BankAdapter` 是唯一写入银行事实的接口。执行门不接受模型传入的风险级别，也不把模型回复当成银行结果。仓库现有演示 API 仍保留；本模块提供可独立测试的执行服务和 FastAPI 工厂，供 C/E 接入。

## 验收场景

1. 未确认、过期确认、参数或计划版本变化都不能写入银行。
2. 同一幂等键重复提交只产生一个银行操作。
3. 两笔并发 600 元转账不能都以黄色绕过 1000 元日额度；第二笔需强验证。
4. 银行成功但响应丢失时进入 `PENDING_UNKNOWN`，Worker 查询后只补记一次成功。
5. 密码/强验证凭据不进入操作参数、Outbox、审计摘要或模型上下文。

## 验证

`python3 -m unittest discover -s tests -v`，并单独运行 `tests/test_execution_gate.py`。
